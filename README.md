# TaskTrackerApi — REST API для учёта задач и проектов (Task Tracker / Kanban)
Учебный проект на ASP.NET Core 8, реализующий базовый функционал системы учёта задач в стиле Kanban: создание, просмотр, обновление 
и удаление задач с поддержкой статусов и приоритетов.
**Предметная область:** автоматизация учёта задач и контроля их жизненного цикла. Система позволяет вести список задач, назначать им статус (ToDo / InProgress / Done), 
приоритет (Low / Medium / High) и отслеживать прогресс — что соответствует типичным сценариям Kanban‑досок и простых трекеров проектов.

### Требования
- Docker Desktop (Windows/macOS) или Docker Engine (Linux)
- .NET 8 SDK (опционально, для локальной разработки вне Docker)

### Сборка и запуск (с версионированием и именем student_work)
cmd:
# 1. Собрать образ
docker build -t tasktracker-api:v1.1 .

# 2. Запустить контейнер
docker run -d -p 5277:8080 --name student_work tasktracker-api:v1.1

После запуска приложение будет доступно:

    Swagger UI: http://localhost:5277/swagger
    Базовый URL API: http://localhost:5277

✅ Проверка работоспособности (Health Check)

В проекте отсутствует эндпоинт /health. Работоспособность сервиса подтверждается успешным ответом 
API — если маршрут работает, сервис считается рабочим (здоровым).
Проверка curl (HTTP‑запрос к своему API. Простой способ протестировать API без браузера):
cmd

curl http://localhost:5277/api/Tasks

Ожидаемый результат: HTTP‑код 200 OK и JSON‑ответ (например список задач).
Это подтверждает, что:

    1.Контейнер student_work запущен и работает правильно.
    2.Приложение внутри контейнера слушает порт и обрабатывает запросы.
    3.Все маршруты API (включая Swagger) доступны.

🗂 Структура проекта: назначение  файлов
TaskItem.cs	
Основной объект предметной области. Содержит поля: Title, Description, Status (ToDo/InProgress/Done), Priority (Low/Medium/High).
Именно эти данные позволяют отображать задачи на Kanban‑доске и фильтровать их по приоритету.	
ITaskService.cs
Определяет, какие операции над задачами должны поддерживаться системой (получить все, создать, обновить, удалить). 
Позволяет легко заменить реализацию (например, на базу данных вместо InMemory).
TaskService.cs
Содержит методы для работы с коллекцией задач: добавление, поиск, изменение статуса, удаление. Сейчас использует InMemory‑хранилище (список в памяти).
Отвечает за состояние задач в рамках жизненного цикла приложения.
TasksController.cs 
Связующее звено между внешним миром и бизнес‑логикой трекера. Обрабатывает HTTP‑запросы (GET, POST, PUT, DELETE) по маршруту /api/Tasks. 
Превращает JSON‑запросы в вызовы сервиса и возвращает JSON‑ответы.	
ASP.NET Web API контроллер. 
Предоставляет REST‑интерфейс для интеграции с фронтендом, мобильным приложением или тестовыми клиентами.
Program.cs
Стартовый файл приложения. Собирает все компоненты в единую работающую систему. Точка входа и настройка приложения.
Здесь регистрируются зависимости (внедрение ITaskService → TaskService), настраиваются маршруты, Swagger, CORS и среда запуска.
